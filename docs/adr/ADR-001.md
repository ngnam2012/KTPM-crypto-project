# ADR-001: Adoption of FastAPI for Backend Infrastructure

**Status:** Accepted

## Context
The system requires a robust backend framework to handle high-frequency market data requests, execute complex mathematical backtesting evaluations, and manage multiple persistent WebSocket connections simultaneously without blocking the main event loop.

## Decision
We chose **FastAPI** over alternatives like Flask or Django.

## Consequences
- **Positive:** FastAPI provides native, first-class `async/await` support which is critical for handling WebSocket multiplexing and I/O bound tasks (like fetching external APIs).
- **Positive:** Automatic generation of OpenAPI (Swagger) documentation significantly accelerates frontend integration.
- **Positive:** Pydantic models ensure strict data validation at the boundaries of our application, catching configuration errors before they reach the Strategy Engine.
- **Negative:** Requires developers to be mindful of `async` vs `sync` function definitions to avoid inadvertently blocking the event loop (e.g., during heavy Pandas computations in the Backtest Evaluator).
