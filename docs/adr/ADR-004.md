# ADR-004: Event-Driven Architecture (EventBus)

**Status:** Accepted

## Context
As features grew, modules began to tightly couple. For example, the `BacktestEvaluator` and `RandomSearch` engine were hard-coded to call the `LeaderboardService` to register results. This created circular dependencies and made unit testing individual modules difficult.

## Decision
We implemented a lightweight, in-process **EventBus** to facilitate Pub/Sub communication across the backend.

## Consequences
- **Positive:** True decoupling. The `RandomSearch` engine now simply publishes a `BACKTEST_COMPLETED` event. It does not know or care if the Leaderboard exists.
- **Positive:** Enables real-time reactivity. WebSockets can easily subscribe to `LEADERBOARD_UPDATED` events and push updates to React clients instantly without polling.
- **Negative:** Program flow becomes implicit rather than explicit. Following the execution path requires searching for event subscribers rather than following a direct call stack.
