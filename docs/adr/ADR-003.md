# ADR-003: Composite Strategy Pattern

**Status:** Accepted

## Context
Users frequently want to combine multiple technical indicators to form robust entry/exit logic (e.g., "Buy if MA crosses over AND RSI is below 30"). Building a unique class for every possible combination is not mathematically scalable.

## Decision
We adopted the **Composite Design Pattern** for trading strategies, specifically building a `CompositeStrategy` class that implements the same `IStrategy` interface as primitive strategies. It supports boolean logic (`AND`, `OR`) and `WEIGHTED` summation scoring.

## Consequences
- **Positive:** Allows infinite nesting and recombination of strategies via simple JSON configurations passed through the API.
- **Positive:** The Random Search Engine can algorithmically discover novel combinations of strategies rather than just tweaking parameters of a single one.
- **Negative:** Increased complexity in the evaluation step; the `WEIGHTED` logic requires careful normalization of signals to avoid one strategy overpowering the others.
