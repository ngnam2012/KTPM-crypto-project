# ADR-005: Database Selection (SQLite vs PostgreSQL)

**Status:** Accepted

## Context

The system requires a relational database to store historical OHLCV candles, strategy definitions, backtest results, trade records, and NLP-analyzed news items. The environment needs to support both seamless local development and robust production deployments.

## Decision

We chose **SQLAlchemy (ORM)** with a dual-target strategy: **SQLite** for local development/MVP, and **PostgreSQL** for production staging.

### Technology Comparison

| Criteria                   | SQLite                             | PostgreSQL                        | MongoDB (NoSQL)   |
| :------------------------- | :--------------------------------- | :-------------------------------- | :---------------- |
| **Data Model**             | Relational                         | Relational                        | Document          |
| **Setup Complexity**       | (None, file-based)                 | (Requires server/Docker)          | (Requires server) |
| **Concurrency**            | File-level lock (write bottleneck) | Row-level lock (high concurrency) | High concurrency  |
| **Relational Integrity**   | Supported                          | Excellent (FKs, constraints)      | Manual handling   |
| **Local Dev Friendliness** | Extremely high                     | Medium                            | Medium            |
| **Decision**               | **Selected for Local/Dev**         | **Selected for Prod**             | Rejected          |

## Consequences

- **Positive:** Utilizing SQLAlchemy abstracts the SQL dialect away from the business logic. Switching from SQLite to PostgreSQL is as simple as updating the `DATABASE_URL` environment variable.
- **Positive:** SQLite requires zero setup, meaning new developers can clone the repository and run the application instantly without configuring dockerized databases.
- **Negative:** SQLite's file-level locking limits concurrency. Heavy automated AI searches running concurrently with frontend API requests might experience `database is locked` errors if not handled carefully (though mitigated in MVP by using in-memory caches and single-threaded search loops).
