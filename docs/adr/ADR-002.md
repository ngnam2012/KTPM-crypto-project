# ADR-002: Plugin Architecture for Strategy Discovery

**Status:** Accepted

## Context
The application needs to support a growing library of trading algorithms (MA Crossover, RSI, Bollinger Bands, NLP Sentiment). Hardcoding these into the main execution path violates the Open/Closed Principle and makes the codebase brittle.

## Decision
We implemented a **Plugin Architecture** using an abstract `IStrategy` interface and a dynamic `StrategyRegistry`.

## Consequences
- **Positive:** Extreme extensibility. Developers can drop a new Python file into the `strategies/implementations/` folder, inherit from `BaseStrategy`, and the system will automatically discover, register, and expose it via the API.
- **Positive:** Core services (Backtest Evaluator, Strategy Search) do not need to be updated when a new strategy is added.
- **Negative:** Debugging a failing strategy requires looking up its registration in the registry rather than tracing a static import path.
